# Kombú admin recovery and execution plan

Baseline: 13 November 2026, revision `75cda48`. The brief uses “Com Modo”; the repository and application identify the product as Kombú.

The panel already has working business logic and fixture coverage for sales, reservations, dashboard finances, and storefront integration. English coverage is partial. Purchase document capture, per-user permissions, and transaction-level recovery still need validation or implementation. Existing checks establish a local baseline. Release remains gated on staging reconciliation and operator workflows.

## Current system

`admin.html` loads `assets/admin.js`, which renders modules, applies business rules, stores local state, and syncs a shared JSON document via `api/state.js`. The API reconciles reservations, validates state and checks for regressions against the stored state. The client also uses dedicated sales, lead, audit, media and authentication routes. `supabase/schema.sql` defines shared state, backups, audit events, leads, email events and sales ledger. `supabase/storefront.sql` defines storefront orders and creator codes. Checkout, webhook and reservations code connect public orders to operational stock. Verify each write boundary in staging before changing the data model.
